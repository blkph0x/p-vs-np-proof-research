# Complete bounded-width resolution closure

For a CNF formula on `n` variables and width bound `w`, this lab saturates the
finite set of all non-tautological clauses of width at most `w` under two
inferences: weakening by adding literals, and binary resolution whose
resolvent has width at most `w`. Initial clauses wider than `w` are excluded,
because they cannot occur in a width-`w` derivation.

The closure is complete for this inference system. Induct on a bounded proof:
each axiom is inserted, each weakening is enumerated, and each resolution is
generated when both parents have entered the closure. Therefore a fixed-point
closure without the empty clause is a certificate that no weakening-resolution
refutation of width at most `w` exists. When the empty clause appears, the
saved axiom, weakening, and resolution records form a replayable refutation.
Explicit clause and step caps return `UNKNOWN` before saturation.

The universe has at most `sum_{i=0}^w 2^i binomial(n,i)` clauses. The simple
implementation scans known clause pairs, so its worst-case work is quadratic
in that universe times the number of pivots, plus weakening generation. This
is an exact bounded-width procedure, not a polynomial algorithm for arbitrary
SAT. The pigeonhole and all-assignment controls test width boundaries; a
satisfiable control and cap-triggered run prevent treating a missing bounded
refutation as an UNSAT result.

For each uncapped control, the audit runs this complete closure at every width
from zero through the widest input axiom. The first width whose closure
contains the empty clause is saved as the minimum refutation width for that
finite instance. The independent review recomputes the same sweep from a
separate implementation and compares every width's status and reason. A
`None` threshold is retained for satisfiable controls, while capped runs are
excluded from the sweep because they are deliberately inconclusive.

Run:

    python -m unittest -v test_resolution.py
    python run_audit.py
    python review.py

## Incremental width ladder

The incremental implementation seeds the width-`w` closure with every clause
from the completed width-`w-1` closure whose width is at most `w`, then adds
the width-`w` axioms and saturates under the same two inferences. Induction on
the derivation length proves equality with a fresh width-`w` closure: the seed
contains all lower-width derivations, and every remaining bounded derivation has
an axiom or parent already in the seeded saturation and is generated by the
same weakening/resolution rules. A capped lower-width run is never used as a
seed.

The saved ladder compares complete clause sets and statuses on the all-
assignment `n=1..4` and pigeonhole `(2,1)`, `(3,2)`, `(4,3)` controls. Candidate
counts show the deterministic work saved by avoiding repeated lower-width
inferences; they are implementation measurements, not machine-independent
runtime bounds. The universe and bit-cost bounds above still apply, so the
ladder remains a parameterized optimization rather than a polynomial SAT
algorithm.

## Literal indexing and the 5-into-4 stress row

`indexed.py` implements the same closure with an index from each literal to
the clauses containing it. When a current clause contains literal `l`, only
the indexed clauses containing `-l` can be resolution parents. Every legal
resolution pair therefore remains enumerated, while clauses with no opposite
literal are never scanned. The index changes work ordering and candidate
counts, not the inference system or its finite closure.

The indexed implementation is independently replayed on the saved exact
controls. On pigeonhole `PHP_5^4`, width 3 reaches a complete fixed point with
2,230 clauses and no empty clause. Width 4 is seeded from that complete width-3
closure, but reaches the explicit one-million-candidate cap with 27,377 known
clauses and status `UNKNOWN`. The cap is a resource boundary: it does not prove
that no width-4 refutation exists. These observations are recorded in
`INDEXED_REPORT.md` and replayed by `review_indexed.py`.

## Bit-mask representation

`bitset.py` stores the positive and negative literals of a clause in two
`n`-bit masks. A clause is tautological exactly when the masks overlap;
resolution clears the two pivot bits and unions the remaining masks. Thus
encoding, weakening, and resolution preserve the same finite clause universe
as the tuple implementation. The exact controls are compared by clause-set
digest against the tuple-indexed solver, and a separate tuple replay checks the
saved PHP(5,4) width-3 closure and a lower-cap width-4 control.

With a ten-million-candidate cap, the bit-mask run reaches the same PHP(5,4)
width-3 fixed point in about 0.8 seconds and advances the seeded width-4 run
to 38,368 known clauses before `STEP_CAP`. The recorded wall-clock values are
machine-specific measurements; they do not imply a complexity-class bound.

## Boolean pebble-game width bridge

Atserias and Dalmau's primary characterization
([paper](https://www.cs.upc.edu/~atserias/papers/width/ccc03.pdf), Theorem 2)
says that a CNF formula has a resolution refutation of width `w` exactly when
Spoiler wins its Boolean existential `(w + 1)`-pebble game. A position is a
partial truth assignment that does not falsify an input clause. The Duplicator
positions form a family closed under restrictions, and whenever fewer than the
pebble limit are occupied, every unpebbled variable must have at least one
truth-value extension in the family.

`pebble.py` computes the greatest such family exactly. It starts with every
non-falsifying position up to the pebble limit and repeatedly removes a
position that loses projection closure or has a variable with neither legal
extension. The empty fixed point is a finite Spoiler certificate; a nonempty
fixed point is a finite Duplicator certificate. `review_pebble.py` replays the
same rows with tuple states and compares the complete round-by-round removal
trace and state digest.

The saved `PEBBLE_RESULTS.json` settles the finite PHP(5,4) width target. The
5-pebble game has an empty fixed point, so a width-4 resolution refutation
exists by the cited theorem. The 4-pebble game retains 54,471 positions, while
the complete bit-mask width-3 closure has 2,230 clauses and no empty clause.
Together these give the exact minimum resolution width **4** for this standard
20-variable, 75-clause encoding. The earlier capped width-4 saturation was
therefore an incomplete search frontier, not evidence against a width-4 proof.

This is a finite proof-complexity result for one encoding. It does not produce
a polynomial SAT algorithm, and it does not resolve P versus NP.

## Uniform PHP width theorem

The standard PHP(n+1,n) encoding has exact minimum resolution width `n` for
every `n >= 2`. The upper bound is constructive: for each injection
`pi:[k] -> [n]`, define the stage clause
`{not p_(1,pi(1)), ..., not p_(k,pi(k))}`. There are `n!/(n-k)!` such clauses.
Starting with the positive axiom for the next pigeon, resolve against the
hole-exclusivity axioms for the already-used holes, then resolve away each
remaining positive literal using the stage `k+1` clause for the corresponding
injection extension. Stage `n` is derived from the extra pigeon, and stage
zero is the empty clause. Every intermediate clause has width at most `n`.

The construction uses exactly
`n * sum(k=0..n) n!/(n-k)! = 2^{O(n log n)}` resolution steps. The repository
generates the complete DAG in `php_width_proof.py`; the independent
`review_php_width_proof.py` reconstructs the formula, validates every axiom,
parent reference, pivot, conclusion, stage count, and width. The full saved
`PHP(7,6)` certificate and the `n=1..6` summary are in
`PHP_WIDTH_CERTIFICATE_N6.json`, `PHP_WIDTH_RESULTS.json`, and
`PHP_WIDTH_REVIEW.json`.

For the lower bound when `n >= 2`, every positive input axiom has width `n`.
If a width-`<n` refutation omitted all positive axioms, its remaining negative
axioms would be satisfied by the all-false assignment, and sound weakening and
resolution could not derive the empty clause. Thus width `n` is optimal. The
degenerate PHP(2,1) instance has minimum width two because its
hole-exclusivity axiom is binary. This uniform theorem concerns resolution
proofs only; its super-polynomial certificate size in the parameter does not
provide a polynomial SAT algorithm or settle P versus NP.
